# רישום בתי הכנסת

`registry.json` הוא הרשימה היחידה של בתי הכנסת שהבוט מכיר. הוספה או שינוי הם
עריכת נתונים בלבד — אין צורך לגעת בקוד.

## מבנה

```json
{
  "id": "makdash-meat",
  "name": "בית כנסת מקדש מעט",
  "icon": "🕍",
  "aliases": ["מקדש מעט", "מקדש-מעט", "בית כנסת מקדש מעט"]
}
```

| שדה | משמעות |
| --- | --- |
| `id` | מזהה קבוע ב־`a-z0-9-`. הוא גם שם הקובץ ב־`data/synagogues/<id>.json` וגם מה שמופיע בכתובת ה־Raw. **אין לשנות אותו אחרי הפרסום הראשון** — האתר מצביע עליו. |
| `name` | השם בעברית, כפי שיוצג באתר ובתצוגה המקדימה בטלגרם. |
| `icon` | אמוג'י לתצוגה. |
| `aliases` | הביטויים שמחפשים בתוך הודעת הגבאי כדי לזהות את בית הכנסת. |

## כללים לכתיבת aliases

הזיהוי הוא חיפוש מחרוזת בתוך ההודעה אחרי נרמול (הסרת גרשיים, כוכביות ומקפים),
והכינוי הארוך ביותר מנצח. לכן:

- **כינוי חייב להיות ייחודי.** `"נווה שלום"` — כן. `"שלום"` — לא, כי כל הודעה
  שמסתיימת ב"שבת שלום" תשויך אליו בטעות.
- **הוסף את כל הכתיבים שמופיעים בפועל**: `"נווה רחמים"` וגם `"נוה רחמים"`.
- אין צורך להוסיף וריאציות של גרשיים או מקפים — הנרמול כבר מטפל בהן.
- אם שתי הודעות מזוהות לבית כנסת שגוי, צמצם את הכינוי שגרם לכך.

## הוספת בית כנסת

1. הוסף רשומה ל־`registry.json`.
2. הרץ `npm run bootstrap` — הפקודה תיצור `data/synagogues/<id>.json` ריק
   ותבנה מחדש את `data/all.json` ו־`data/index.json`. היא לא נוגעת בקבצים קיימים.
3. בדוק את הזיהוי על הודעה אמיתית לפני שמפעילים בשטח:

   ```bash
   node src/cli.js path/to/message.txt
   ```

4. עשה commit ו־push. ההרצה הבאה של ה־Action כבר תכיר את בית הכנסת החדש.

## כשההודעה לא מזוהה

זה לא נכשל בשקט. אם אף כינוי לא נמצא, התצוגה המקדימה בטלגרם מגיעה עם מקלדת
בחירה של כל בתי הכנסת, ואפשר גם לשייך ידנית:

```
/shul <pending-id> <synagogue-id>
```

`/list` מציג את כל המזהים.
