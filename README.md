# זמני תפילות — ארכיון

> **הפרויקט הזה עבר.** הקוד החי נמצא ב־[`AfriatMichi/TFILA_NEW`](https://github.com/AfriatMichi/TFILA_NEW)
> תחת `worker/bot/`, כחלק מה־Worker של הפורטל.

## למה

הבוט שנבנה כאן עבד. מה שלא עבד היה מה שמפעיל אותו.

הארכיטקטורה המקורית הייתה GitHub Actions שקורא `getUpdates` בתזמון. כל שאר
המערכת פעלה ללא דופי — `workflow_dispatch` הצליח 10 מתוך 10 — אבל המתזמן של
GitHub סיפק **הרצה אחת מתוך 11 צפויות**, והיא באיחור של 48 דקות. נוסו ארבע
תצורות cron שונות (`*/30`, `*/5`, `7 * * * *`, `11,26,41,56`); אף אחת לא עזרה.
GitHub מתעד את `schedule` כ־best-effort, וכאן הוא פשוט כמעט לא ירה.

לכן הבוט עבר ל־webhook על Cloudflare Worker, ובתוך ה־Worker הקיים של הפורטל ולא
לצדו — הוא קיים אך ורק כדי להזין את הפורטל, והם ממילא חלקו מסד נתונים ודומיין.

## מה השתנה במעבר

- **תגובה מיידית** במקום המתנה לחלון הרצה. גם הכפתורים עובדים סוף סוף — קודם
  `answerCallbackQuery` תמיד נכשל ב־"query is too old".
- **הנתונים ב־D1** ולא בקבצי JSON כאן. הפורטל קורא אותם ישירות, בלי קפיצת רשת
  ובלי cache של 5 דקות.
- **ההיסטוריה פרטית.** טבלת `BOT_publications` החליפה את יומן ה־commits, ואיתה
  גם `state/archive/` — שבו כל הודעת גבאי הייתה גלויה לכל העולם בריפו ציבורי.

הניתוח עצמו — ה־parser מבוסס־החוקים, מילון התפילות והחגים, נרמול העברית וכללי
המניינים — עבר verbatim. הוא לא נכתב מחדש.

## מה נשאר כאן

`data/` בלבד — צילום המצב של מה שפורסם עד המעבר. הוא זרע ההגירה ל־D1
(`migrations/0006_seed_bot_documents.sql` בריפו החדש) ועוגן הגלגול אחורה.
ההיסטוריה המלאה של הפיתוח נשמרת ב־git.

הקבצים כאן **כבר לא מתעדכנים** ואף אחד לא קורא מהם.
